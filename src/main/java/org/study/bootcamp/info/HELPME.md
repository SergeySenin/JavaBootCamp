Инструменты и практики написания кода
1.  Обработка и валидация входных данных
1)  Делай явные проверки входных параметров.
2)  Приводи входные данные к одному виду.
3)  Валидацию можно реализовывать разными способами:
    выносить в методы, вешать аннотации или использовать библиотеку org.apache.commons.
4)  При работе с числами заранее проверяй границы и формат данных.
5)  При сравнении строк учитывай регистр и пробелы — нормализуй вход.

2.  Работа с коллекциями и массивами
1)  Для списков и массивов всегда контролируй индексы и длины.
2)  Перед работой с массивами и коллекциями просматривай через IDEA все их методы.
3)  Чёткие контракты коллекций: «снимок» (snapshot) vs «живой вид» (live view).
    Наружу — только снимки/неизменяемые коллекции.
4)  Для результатов используй неизменяемые коллекции: List.of/Set.of/Map.of или копии.

3. Использование Stream API и Optional
1)  В Stream сначала фильтруй, потом преобразуй, потом считай/собирай — так проще читать.
2)  Для группировок и подсчётов используй Collectors (groupingBy, counting, joining).
3)  Optional используй аккуратно: сначала проверяй isPresent()/orElse*, а get() не вызывай без проверки.
4)  Для сортировки используй Comparator.comparing и thenComparing.
5)  Длинные цепочки Stream/Optional разбивай на маленькие методы: выдели шаги в отдельные функции.

4.  Упрощение и читаемость кода
1)  Использование copyOf, computeIfAbsent, getOrDefault и var значительно упрощает рутинный и сложный код.
2)  Используй готовые функциональные интерфейсы из Java (Predicate, Function, Supplier, Consumer).
3)  Если лямбда — просто вызов метода, пиши ссылку на метод: Object::method.
4)  Упрощай код: один метод — одна понятная задача, без лишних побочных эффектов.
5)  Выделяй повторяющиеся куски логики в отдельные методы и переиспользуй их.
6)  Дай переменным и методам понятные имена, чтобы код читался без комментариев.
7)  Осторожное использование библиотеки Lombok поможет писать более краткий и читаемый код.
8)  Осмысленное объявление классов рекордами поможет писать более краткий и читаемый код.

5.  Безопасность данных и архитектура
1)  Минимизируй изменяемость данных: создавай новые объекты вместо правки старых.
2)  Инъекция зависящих от среды вещей (время/случайность/IO) упрощает тестирование.
3)  Отделяй бизнес-логику от вывода в консоль/файл.

6.  Тестирование и вывод
1)  Форматируй вывод единообразно, чтобы тестировать и читать было проще.

7.  Полезные импорты
1)  Иногда может помочь: import java.util.concurrent.atomic.AtomicInteger;.
2)  Иногда может помочь: import java.math.*;.
