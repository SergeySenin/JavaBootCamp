Структура Java-проекта: src, package, classpath

## 1. Папка `src` — где живёт ваш код

Если бы Java-проект был домом, то папка `src` была бы уютной гостиной, где собираются все
основные обитатели — ваши классы. Именно сюда помещаются все исходные файлы с кодом,
а не в корень проекта, не в папку с настройками и не на рабочий стол, даже если очень
хочется.

### Почему исходники нужно отделять от всего остального?

* В папке `src` хранятся только файлы, которые вы пишете руками: `.java`.
* Всё, что появляется в процессе сборки, например `.class`-файлы и временные файлы,
  складывается в другие папки: `out`, `build`, `target` и т. д.
* Это облегчает навигацию, делает проект чище, а IDE — счастливее.

Пример структуры простого проекта:

```text
MyFirstProject/
├── .idea/           # служебные файлы IntelliJ IDEA, не трогаем
├── out/             # тут появляются скомпилированные .class-файлы
├── src/             # вот тут живёт ваш исходный код
│   └── Main.java
├── MyFirstProject.iml
└── README.md
```

Важно: всё, что вы пишете сами — классы, пакеты, интерфейсы, — должно быть в папке `src`.
Не кладите туда картинки, музыку и секретные рецепты: для этого есть другие папки.

## 2. Пакеты package

В Java принято группировать классы по пакетам. Это как папки в файловой системе, только
для классов. Пакеты помогают:

* избежать конфликтов имён, если в проекте есть два класса `Main`: в разных пакетах они
  не будут мешать друг другу;
* логически структурировать код, например `com.javarush.tasks`, `com.mycompany.utils`;
* управлять доступом к классам и методам.

### Синтаксис объявления пакета

В начале каждого Java-файла, до всех `import` и до объявления класса, пишется строка:

```
package com.javarush.lesson05;
```

Это значит: класс из этого файла принадлежит пакету `com.javarush.lesson05`.

Важно: папки в файловой системе должны совпадать с именем пакета. Если у вас написано:

```
package com.javarush.lesson05;
```

то путь к файлу будет таким:

```text
src/com/javarush/lesson05/Main.java
```

### Как создать пакет в IntelliJ IDEA

1. В панели проекта кликните правой кнопкой мыши по папке `src`.
2. Выберите **New → Package**.
3. Введите имя, например `com.javarush.lesson05`. IntelliJ IDEA сама создаст вложенные папки.
4. Теперь создайте новый класс внутри этого пакета: кликните правой кнопкой мыши по папке
   `com.javarush.lesson05`, выберите **New → Java Class** и введите имя класса.

Пример:

```text
src/
└── com/
    └── javarush/
        └── lesson05/
            └── User.java
```

### Почему нельзя просто всё складывать в `src`?

Если положить все классы вперемешку, проект быстро превратится в свалку, где найти нужный
файл будет сложнее, чем найти зарядку для ноутбука в студенческом общежитии. Используйте
пакеты — так будет проще масштабировать проект, подключать сторонние библиотеки и делить код
между разными командами.

## 3. Полное имя класса

В Java класс может находиться в именованном пакете. Пакет — это часть библиотеки классов.
Например:

* класс `System` лежит в пакете `java.lang`. Его полное имя — `java.lang.System`;
* класс `Scanner` лежит в пакете `java.util`. Его полное имя — `java.util.Scanner`;
* класс `ArrayList` тоже лежит в пакете `java.util`. Его полное имя — `java.util.ArrayList`.

То есть полное имя класса — это имя пакета + точка + имя класса.

Попробуем использовать это в коде:

```
java.util.Scanner sc = new java.util.Scanner(System.in);
String name = sc.nextLine();
System.out.println("Привет, " + name);
```

Здесь мы явно пишем `java.util.Scanner`. Компилятор понимает, о каком именно классе идёт речь,
даже если в программе есть другие классы с именем `Scanner`.

Это очень важно: простое имя класса может совпадать, но полное имя обычно остаётся уникальным.

### Зачем вообще нужно полное имя?

Представьте, что у нас есть два разных класса `Date`:

* `java.util.Date` — старый класс для работы с датами;
* `java.sql.Date` — дата для работы с базами данных.

Если вы просто напишете:

```
Date d = new Date();
```

компилятор может не понять, какой именно `Date` вы хотите использовать. Но если написать
полное имя:

```
java.util.Date d1 = new java.util.Date();
java.sql.Date d2 = new java.sql.Date(System.currentTimeMillis());
```

путаницы не будет.

## 4. Инструкция import

Писать каждый раз полное имя класса неудобно. Именно для этого в Java существует инструкция
`import`.

Если мы пишем:

```
import java.util.Scanner;
```

это значит: «В этой программе я буду использовать класс `Scanner` из пакета `java.util`».
После этого мы можем писать просто:

```
Scanner sc = new Scanner(System.in);
```

и компилятор поймёт, что речь идёт именно о `java.util.Scanner`.

### Обычный import: один класс

Это самый распространённый вариант. Мы указываем конкретный класс:

```
import java.util.Scanner;
import java.util.ArrayList;
```

Теперь можно писать короткие имена: `Scanner`, `ArrayList`.

### Импорт всего пакета через *

Иногда в программе используется много классов из одного пакета. Тогда можно написать:

```
import java.util.*;
```

Это значит: «Разрешить использовать все классы из пакета `java.util` без полного имени».

Теперь можно писать:

```
Scanner sc = new Scanner(System.in);
ArrayList<String> list = new ArrayList<>();
```

Но важно помнить: `import java.util.*;` импортирует только классы из пакета `java.util`,
но не из его подпакетов. Например, класс `java.util.concurrent.ConcurrentHashMap` сюда
не попадёт. Его нужно импортировать отдельно.

### Что нельзя сделать с import

* `import` нельзя использовать внутри метода — он пишется только в начале файла.
* `import` не загружает классы в память. Он только говорит компилятору, где искать класс.
* `import` не может заменить полное имя, если в коде нужно одновременно использовать два
  класса с одинаковым простым именем.

## 5. Classpath — как Java ищет ваши классы

Classpath — это маршрут, по которому Java ищет ваши классы, когда запускает программу.
Можно представить его как список папок и библиотек, где Java будет искать нужные
`.class`-файлы, то есть скомпилированные версии ваших `.java`-файлов.

IntelliJ IDEA сама добавляет в classpath папку со скомпилированными классами, например
`out/production/ProjectName`, а также подключённые библиотеки. То есть если вы написали класс
в пакете `com.javarush.lesson05`, Java будет искать его по пути:

```text
out/production/ProjectName/com/javarush/lesson05/Main.class
```

### Как работает classpath в IntelliJ IDEA?

* Когда вы запускаете программу через IDE, она автоматически подставляет нужный classpath.
* Если вы запускаете программу из командной строки, вам нужно явно указать classpath
  с помощью флага `-cp` или `-classpath`.
* Все классы из вашего проекта и подключённых библиотек должны находиться в папках
  или файлах, которые указаны в classpath.

## 6. Организация кода в проекте

### Один public-класс — один файл

В Java принято, чтобы каждый `public`-класс был в отдельном файле, который называется так же,
как и сам класс. Например, если у вас класс `Person`, то файл должен называться `Person.java`.

Пример:

```text
src/com/javarush/lesson05/Person.java
```

```
package com.javarush.lesson05;

public class Person {
    String name;
}
```

### Имена файлов и классов должны совпадать

Если класс называется `MySuperClass`, то файл должен называться `MySuperClass.java`.
Это не просто прихоть, а требование компилятора Java для `public`-классов. Если перепутать,
получите ошибку на этапе компиляции.

### Где хранить ресурсы: картинки, текстовые файлы?

* Для ресурсов обычно создают отдельную папку, например `resources` или `res`.
* В IntelliJ IDEA можно добавить такую папку через правый клик по папке:
  **Mark Directory as → Resources Root**.
* Java-код может обращаться к этим файлам через `classpath`.

Пример структуры:

```text
MyFirstProject/
├── src/
│   └── com/javarush/lesson05/
│       └── Main.java
├── resources/
│   └── config.txt
```

## 7. Типичные ошибки при работе со структурой проекта

### Несовпадение структуры папок и пакета

Если в начале файла написано:

```
package com.javarush.lesson05;
```

а файл лежит в `src/Main.java`, компилятор выдаст ошибку. Всегда следите, чтобы папки
соответствовали имени пакета.

### Несовпадение имени файла и класса

Если `public`-класс называется `Person`, а файл — `People.java`, получите ошибку:

```text
class Person is public, should be declared in a file named Person.java
```

### Ручное перемещение файлов без обновления пакета

Если вы переместили файл в другую папку, но забыли поменять строку `package`, программа
не скомпилируется. Делайте это в окне Project в IntelliJ IDEA — она сама обновит `package`.

### Ресурсы не добавлены в classpath

Если вы храните файлы, например текстовые, вне папки `resources` и не пометили папку как
**Resources Root**, программа не сможет найти их через classpath.
