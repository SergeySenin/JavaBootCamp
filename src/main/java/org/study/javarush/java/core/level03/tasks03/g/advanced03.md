# Задание 03. Система безопасности банковского перевода

Вы разрабатываете консольную программу, которая проверяет банковский перевод перед его выполнением.

Пользователь вводит сведения о счёте, устройстве и переводе.
Программа должна преобразовать эти данные в логические признаки, определить уровень риска,
выполнить необходимые проверки безопасности и принять решение: разрешить перевод или отклонить его.

## Структура программы

Создайте класс «решение» (`Solution`).

В классе создайте главный метод программы (`main`).

Для чтения данных с клавиатуры подключите класс «сканер» (`Scanner`) из пакета `java.util`.

Создайте объект «консоль» (`console`), который
считывает данные из стандартного потока ввода (`System.in`).

## Ввод данных

Программа должна последовательно считать следующие значения.

С помощью метода «считать строку» (`nextLine()`) получите:

1. «имя клиента» (`customerNameInput`);
2. «статус счёта» (`accountStatusInput`);
3. «статус устройства» (`deviceStatusInput`);
4. «код подтверждения» (`confirmationCodeInput`).

После этого с помощью метода `nextInt()` получите:

5. «текущий баланс» (`accountBalance`);
6. «сумму перевода» (`transferAmount`);
7. «возраст счёта в днях» (`accountAgeDays`);
8. «количество неудачных попыток входа» (`failedLoginAttempts`).

## Допустимые текстовые значения

Для статуса счёта (`accountStatusInput`) используются значения:

* `"ACTIVE"` — счёт активен;
* `"INACTIVE"` — счёт неактивен.

Для статуса устройства (`deviceStatusInput`) используются значения:

* `"TRUSTED"` — доверенное устройство;
* `"UNKNOWN"` — неизвестное устройство.

Правильный код подтверждения:

`BANK-2026`

Сравнение содержимого строк выполняйте методом «сравнить строки по содержимому» (`equals()`).

Для проверки строк не используйте оператор `==`.

## Подготовка данных

### 1. Имя клиента

Создайте переменную «имя клиента» (`customerName`) типа «строка» (`String`).

Запишите в неё значение `customerNameInput` после
удаления пробелов в начале и конце строки методом `trim()`.

### 2. Состояние счёта

Создайте переменную «счёт активен» (`isAccountActive`) типа «логический» (`boolean`).

Она должна содержать результат проверки:

`accountStatusInput` равен `"ACTIVE"`.

### 3. Доверенное устройство

Создайте переменную «устройство доверенное» (`isTrustedDevice`) типа `boolean`.

Она должна содержать результат проверки:

`deviceStatusInput` равен `"TRUSTED"`.

### 4. Правильность кода

Создайте переменную «код правильный» (`isCodeCorrect`) типа `boolean`.

Она должна содержать результат сравнения `confirmationCodeInput` с правильным кодом `"BANK-2026"`.

## Числовые проверки

Создайте следующие переменные типа `boolean`.

### «Достаточно средств» (`hasEnoughBalance`)

Значение должно быть `true`, если сумма перевода (`transferAmount`)
**меньше или равна** текущему балансу (`accountBalance`).

Для проверки используйте оператор «меньше или равно» (`<=`).

### «Крупный перевод» (`isLargeTransfer`)

Перевод считается крупным, если его сумма **больше `100000`**.

Для проверки используйте оператор «больше» (`>`).

### «Новый счёт» (`isNewAccount`)

Счёт считается новым, если его возраст **меньше `30` дней**.

Для проверки используйте оператор «меньше» (`<`).

### «Слишком много неудачных попыток» (`hasTooManyFailedAttempts`)

Значение должно быть `true`, если количество неудачных попыток входа **больше или равно `3`**.

Для проверки используйте оператор «больше или равно» (`>=`).

## Основная предварительная проверка

Создайте переменную «основные условия выполнены» (`basicConditionsPassed`) типа `boolean`.

Основные условия считаются выполненными только одновременно в следующих случаях:

* счёт активен;
* средств достаточно;
* нет слишком большого количества неудачных попыток входа.

При построении выражения используйте:

* логическое «И» (`&&`, AND);
* логическое «НЕ» (`!`, NOT).

То есть значение `hasTooManyFailedAttempts` необходимо логически инвертировать.

## Тип перевода

Создайте переменную «тип перевода» (`transferType`) типа `String`.

Значение должно определяться **тернарным оператором** (`?:`):

* `"LARGE"`, если `isLargeTransfer == true`;
* `"STANDARD"` в противном случае.

Не используйте `if-else` для определения `transferType`.

## Уровень риска

Создайте переменную «уровень риска» (`riskLevel`) типа `String`.

Определите её значение с помощью цепочки:

`if → else if → else`

Правила:

1. Если `hasTooManyFailedAttempts` равно `true`, уровень риска:

   `HIGH`

2. Иначе, если перевод крупный **или** счёт новый, уровень риска:

   `MEDIUM`

3. Во всех остальных случаях:

   `LOW`

Во второй проверке используйте логическое «ИЛИ» (`||`, OR).

## Предупреждение о крупном переводе

Используйте отдельный условный оператор (`if`) **без блока `else`**.

Если перевод является крупным (`isLargeTransfer`), программа должна вывести:

```text
SECURITY NOTICE: additional verification is required.
```

Для обычного перевода эта строка выводиться не должна.

## Правила разрешения перевода

Создайте переменную «перевод разрешён» (`transferAllowed`) типа `boolean`
и первоначально присвойте ей значение `false`.

После этого реализуйте многоуровневую проверку.

### Первый уровень

С помощью `if` проверьте значение `basicConditionsPassed`.

Дополнительные проверки должны выполняться
**только в том случае**, если основные условия уже выполнены.

Если основные условия не выполнены, `transferAllowed` должно сохранить значение `false`.

### Второй уровень

Внутри предыдущего `if` создайте вложенную конструкцию `if-else`.

#### Если перевод крупный

Если `isLargeTransfer` равно `true`,
перевод разрешается только тогда, когда одновременно выполняются два условия:

* счёт не является новым;
* код подтверждения правильный.

Для проверки используйте выражение с:

* логическим «НЕ» (`!`);
* логическим «И» (`&&`).

Если оба условия выполнены, присвойте:

`transferAllowed = true`

В противном случае оставьте значение `false`.

#### Если перевод обычный

В ветке `else` перевод разрешается, если выполняется хотя бы одно условие:

* устройство является доверенным;
* введён правильный код подтверждения.

Используйте логическое «ИЛИ» (`||`).

Если хотя бы одно условие выполнено, присвойте:

`transferAllowed = true`

В противном случае значение должно остаться `false`.

## Изменение баланса

Создайте переменную «баланс после операции» (`balanceAfterTransfer`) типа `int`.

Сначала присвойте ей текущее значение `accountBalance`.

После завершения всех проверок используйте отдельный `if` **без `else`**.

Если `transferAllowed` равно `true`, уменьшите `balanceAfterTransfer` на значение `transferAmount`.

Если перевод запрещён, значение баланса изменяться не должно.

## Итоговый статус

Создайте переменную «статус перевода» (`transferStatus`) типа `String`.

Определите её с помощью тернарного оператора (`?:`):

* `"APPROVED"`, если `transferAllowed` равно `true`;
* `"DECLINED"`, если `transferAllowed` равно `false`.

Все значения в квадратных скобках должны попадать в вывод из соответствующих переменных.

## Требования к логическим выражениям

Логические значения, которые можно получить непосредственно результатом сравнения,
должны вычисляться как логические выражения.

Например, переменная типа `boolean` не должна определяться по избыточной схеме:

`условие ? true : false`

Для неё достаточно непосредственно сохранить результат условия.

Тернарный оператор используйте только там, где
по условию выбирается одно из двух значений типа `String`: для `transferType` и `transferStatus`.

## Критерии выполнения

Задание выполнено правильно, если:

1. программа компилируется и запускается;
2. исходные данные считываются с клавиатуры;
3. строки сравниваются методом `equals()`, а не оператором `==`;
4. основные проверки сохраняются в переменных типа `boolean`;
5. `basicConditionsPassed` вычисляется с помощью `&&` и `!`;
6. уровень риска определяется конструкцией `if-else if-else`;
7. оператор `||` используется при определении уровня риска и при проверке обычного перевода;
8. крупный и обычный переводы обрабатываются разными ветками вложенного `if-else`;
9. дополнительная проверка крупного перевода выполняется только после успешной основной проверки;
10. новый счёт не может выполнить крупный перевод;
11. крупный перевод нельзя подтвердить только доверенным устройством — требуется правильный код;
12. обычный перевод можно подтвердить либо доверенным устройством, либо правильным кодом;
13. при запрещённом переводе баланс не изменяется;
14. `transferType` и `transferStatus` определяются простыми тернарными операторами;
15. программа корректно проходит основной и дополнительные тесты.
